## Mask, media paths and state

`assign_groups` gives each supported media token its earliest window, including shared ASR boundary/header tokens, and assigns unsupported media to the separate group N. Scaffolding stays -1. The mask permits causal scaffold keys for any row and causal same-group media keys only for media rows. Thus scaffold rows cannot read media, groups cannot relay media through scaffolding, no future edge is introduced, and every row retains its diagonal. The mask is active on every language-layer self-attention during a fresh prefix only, with a visited-layer assertion. It is disabled before the global-question, forced-answer and all local-query extensions. Shared membership does not create a shared-state bridge.

I also read the actual installed transformer sources on `uoa-lab2`, without running a remote model: `HateVLM/lib/python3.12/site-packages/transformers/{models/qwen3_vl/modeling_qwen3_vl.py,vision_utils.py,integrations/sdpa_attention.py}`. The installed package records version 5.15.1. Its text-attention call signature matches the pre-hook's keyword/positional handling. Both explicit-causal and factorized masks reach the same SDPA interface as additive masks of identical shape/dtype and use the same explicit-mask GQA replication path.

In that source, `get_vision_cu_seqlens` defaults to separate `h*w` attention segments for each temporal slice of each grid entry. Vision SDPA splits Q/K/V at those boundaries before attention and concatenates results afterward. Patch embedding operates on separate packed patches, spatial merging stays within each valid image grid, and DeepStack injects the corresponding visual feature into its matching visual row by addition. There is no cross-image attention or DeepStack mixing route bypassing the language mask for the supplied still-image inputs. Frame/header/image token memberships use the unchanged shared `token_regions` expansion and exact processor-token equality assertion.

Each arm starts a fresh prefix after resetting RoPE state. No native cache is reused as a factorized cache. The recomputed causal/factor global margins are diagnostics only: downstream `z_video` and the forced Yes/No answer remain the original native values in all three arms. Question/answer states are recomputed on each arm's prefix, not copied from native states. Local branches crop back to that arm's prefix-plus-global-question-and-answer length; missing speech and ordinary full-context suffix access are preserved.

## Numerical control and independent CPU evidence

Requiring bitwise equality between native implicit SDPA and an explicit dense mask would not be justified. The primary experiment includes a complete explicit-causal arm before seeing performance; the promotion gate requires within-video gains against it as well as native/current baselines. Native ordinary restoration still requires exact equality. This does not conflate kernel drift with the factorization mechanism.

Independent test and result: `runs/20261003_m1_factorizer/independent_review/check_factorizer.{py,json}`. Run locally on CPU with CUDA disabled, torch 2.7.1+cu128 / transformers 4.57.6. Changing the later image cannot affect earlier-group K/V. Native prefix states and unrestricted suffix queries remain sensitive to the intervention. Full multimodal native versus explicit-causal computation is exact under the fixed math backend. Native outputs and model weights are restored exactly. Separate reachability checks cover earliest shared-token ownership and the unsupported-media group.
