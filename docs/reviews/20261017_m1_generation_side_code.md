### Blocking

1. **`analyze.py:193` — the affine score `s_aff` enters the decoded method through the video key, while README §2 declares it raw-curve only.**
   - What the code does: for every speech window `one["z"] = max(z_visual, s_aff)` (`analyze.py:191-193`). The fixed time level reads that field: `twolevel.py prep()` stores `w["z"]`, `intercept(v) = z_video + mean(w["z"])` is the video key K, and with `--key calib` the decoded score is `key_calibration(K) + centred rank` (`twolevel_r2.py:734-749, 819-830`). The `--transform nscore` block rewrites only the per-modality emissions `w["y"][m]`; its own comment says "the key keeps the raw reads" (`twolevel_r2.py:716-726`). So the per-video constant that drives the pooled frame ROC-AUC and PR-AUC of the decoded arm is built from `s_aff`, i.e. from the arm's primary score after the corpus-level mean/std matching to r6's `z_speech`.
   - What the README declares: §2 "nscore 变换按语料对读数做秩正态化，所以 s 的量纲不影响时序层" and "预测文件里的原始 `score_curve` 只供原始读数评测：z = max(z_visual, s_aff) ... 只为了和 z_visual 同量纲". Both sentences are false for the key path. The r6_bma reference built the same key from `max(z_visual, z_speech)` (checked: in `base_gridA` all 6580 speech windows have `z == max(z_visual, z_speech)`, all 779 silent windows `z == z_visual`), so under the current code the comparison against r6_bma mixes two changes: the new speech emission in the chain, and a new video key. No label is involved, so this is not a leak; it is an undeclared path into the authoritative numbers.
   - What it would change: the pooled ROC/PR of `main_decoded/<arm>/metrics.json` (within is unaffected, the key is a per-video constant), hence the rule-8 gate and the attribution of any pooled difference. The ablation "z_speech 换回 r6" would also revert the key, so the ablation could not separate the two effects.
   - Minimal fix (either one, declared in README §2 before the run):
     (a) keep the key identical to r6_bma: `one["z"] = <r6 window>["z"]` (the r6 window is `ref["extra"]["windows"][t["i"]]`), and keep `s_aff` only in the raw `score_curve`; then the decoded difference comes only from the replaced emission, which is what §2 currently claims; or
     (b) keep the code and amend §2 to say that `max(z_visual, s_aff)` also forms the video key through `intercept()`, with the affine (corpus mean/std of s matched to r6 `z_speech`) listed as a declared label-free constant of the method.
