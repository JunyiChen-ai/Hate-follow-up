## 确认

- R4只建一次不带tree的native20/fullASR/global+自身hard stance缓存。reference V/S先独立读取，再从同一恢复后的native cache分别读取带相同local packet的new V/new S；没有R3共享extension，也没有重新测G或复用R2分数。空native speech保持缺失。
- local_content提取保持既有V输入顺序：ancestor context+LOCAL_HEADER、实际source time/image、该模态原yes/no question。新S只是以原speech question调用同一实际像素路径。local_visual仍检查fresh full input/grid与prefix3维positions，并在forward正常/异常后crop及恢复delta；V/S不读彼此答案。
- trace新增实际suffix_text/IDs及原有paths/counts。当前输入校验重新加载native原图/ASR、按base自身stance重建msgs/head/history及P，逐窗重新构建V/S内容、打开实际local图像、重新processor编码，核token/text/path/imagecounts/availability；配合record validator核当前packet与margin、原生G/stance、曲线、窗口和cost。resume和prepare都调用这条绑定，不只检查旧字段长度。
- 生产调用`3+W+available_S`，paired实际为`base.calls+new.calls-3+diagnostic`。smoke各一次first V、first available S的fresh/clone；若speech到中间窗才出现，诊断在那个窗执行。生产时间包括全部旧acquisition+native prefix+new V+new S，reference与clone单列；new S新增图像数独立汇总。
- analyze在GT评测前要求完整expected集合、原native G/窗口/曲线exact，并逐窗要求new V与保存的R2 new V精确一致；R2仅在prepare读取，不进入R4评分。V/S fresh与clone覆盖按实际语音可用性检查。canonical evaluator/fixedr6不变，diagnose仍是postscore。r4独立输出路径与命令分派明确，R1/R2/R3默认行为兼容。
