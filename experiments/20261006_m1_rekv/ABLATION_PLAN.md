## Matching, wrong donors and ownership: precise constraints

Persist a per-layer manifest for each arm: actual source ID, actual PTS, presented PTS (if different), true ownership, operational LOCAL/context role, direct and inherited ancestors, block/image/text token counts, selected count, source token sum, logical positions and suffix start. Selection is determined entirely from inputs and fixed R0 traces, never GT or prediction quality. On selection-only controls the same image pool/density/prompt is available, LOCAL is identical, native prefix is exact, and source encoding cost is identical. Counts alone do not establish token matching: timestamps change text length and occasional image grids differ.

A read-only audit of all 333 source metadata records (`runs/20261006_m1_rekv/ablation_planner/own_notes.json`) found full disjoint exact per-block token matching possible in 77,415/135,504 HateMM layer cases and 84,780/129,168 HateClipSeg cases; counts include empty remote cases and are an upper feasibility diagnostic, not intervention exposure. There are 1,152 HateMM layer cases with no spare remote block at all. Therefore D0 must not promise that all four donors change everywhere. For each token bucket choose as many unique nonoriginal IDs as possible, then retain the minimum necessary original IDs. A fixed cyclic preference starts after the greatest original source index within the bucket, wrapping in increasing index order. Return unique IDs; no duplicates, cropping, synthetic filler or covert token padding. Empty/no-LOCAL cases preserve declared native fallback.

C1 and L2 can always match token multisets because original IDs stay candidates; report how many selections actually change. D0 should additionally report unchanged, partially changed and fully changed windows/layers; original-donor overlap, donor PTS distance, image-token counts and ancestry overlap. Bucket matching of complete block length is exact for attention budget but can hide text/image composition changes; show both. If content interventions have low exposure, they are inconclusive; do not drop unexposed videos from the primary table. Optional exposed-subset diagnostics must show denominators and cannot satisfy the main gate.

T0 needs an actual preflight before GPU submission: tokenize candidate timestamp substitutions with the real processor; create a deterministic maximum cross-window permutation within each timestamp-token-length group (ties ascending actual source index), leaving unavoidable fixed points explicitly marked. Record true and presented times separately. Full source block token count, image rows, pixel arrays and spatial positions must match the truthful comparator; declared times must actually cross ownership boundaries in selected blocks for the current question. Freeze R0 selection/local IDs and use identical block packing order, so retrieval or changed token budgets cannot explain the result. The source construction must be rerun with the incorrect visible timestamp, propagating into descendant KV. Consequently T0 measures the whole timestamp-conditioned memory binding, not a perfectly isolated final-reader role coefficient. Do not pretend changing posthoc metadata changes model-visible content. If exact-token cross-window reassignment is sparse, report that limitation and request a revised concrete matching design from this reviewer before calling it a binding test; do not silently relax matching or distort main inputs.

No additional prompt-only role deletion is required. In this implementation LOCAL/context is derived from actual timestamps and window membership; there is no independent learned role module. T0 is the explicit wrong ownership test. A separate role claim would require a separately specified actual computational intervention, not renaming T0 twice.

## Context ancestry and source density

L0 is **no explicit remote read**, not no remote information. Each LOCAL source block was encoded from a native whole-video prefix and up to four preceding contextual source blocks, with inherited older observations. C0, C1, L1, L2 and D0 match this source memory, but different chosen blocks have different ancestors. Report ancestor union sizes, overlap with LOCAL ancestors, and maximum temporal span; this describes rather than erases the confound.

H0 removes source-to-source direct/inherited ancestry by construction. It still contains native global context and must not be called isolated-frame vision. Run H0+L0 as a priority-2 companion if H0 or L0 makes ancestry important: their contrast tests explicit retrieval when added source ancestry is absent. This costs one more query pass after H0's already rebuilt source memory. Source source-density changes are not initially needed: main-versus-L0 shares the same 0.5fps source acquisition, and C1/D0 isolate retrieval at equal counts/tokens. Native r6 versus L0 measures the whole added LOCAL/context package and does not attribute its effect to retrieval. Removing compulsory LOCAL is outside this candidate's allowed method definition and is not prescribed as a new method.

Sensitivity is secondary: only after priority-1 results support a meaningful retrieval effect, run remote k=2 and k=8 (k=0 L0, k=4 main already exist) with identical source memory. Report all outcomes and worst values, never choose a corpus-specific k. Increasing k changes content and compute, so it is robustness/cost evidence, not a mechanism deletion. Source-history h=0 is H0; do not run an arbitrary h sweep or source-fps sweep merely to find a better test number.
